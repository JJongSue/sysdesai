# 검색 엔진 설계

> Source: https://www.sysdesai.com/learn/case-studies/search-engine

## 문제 정의

웹 검색 엔진은 인터넷을 크롤링하고, 수십억 개의 페이지를 인덱싱하며, 200ms 이내에 쿼리에 대한 가장 관련성 높은 결과를 반환합니다. 이것은 인류가 구축한 가장 복잡한 엔지니어링 문제 중 하나이지만, 면접에서는 네 가지 명확하게 정의된 서브시스템으로 분해할 수 있습니다: **크롤링(Crawling)**, **인덱싱(Indexing)**, **랭킹(Ranking)**, **서빙(Serving)**.

## 요구 사항

- 웹을 크롤링하고 인덱싱합니다 (약 100억 개 페이지, 30일마다 재크롤).
- 200ms 이내에 쿼리에 대한 상위 10개 관련 결과를 반환합니다.
- 자동완성/쿼리 추천을 지원합니다.
- 피크 시 초당 10만 쿼리를 처리합니다.
- 인덱스 신선도 유지: 새 페이지는 24시간 이내에 인덱싱됩니다.
- 구문 검색, 불리언 연산자, site: 필터를 지원합니다.

## 용량 추정

| 지표 | 추정치 |
| --- | --- |
| 인덱싱된 페이지 수 | 100억 |
| 평균 페이지 크기 (HTML 제거 후 텍스트) | 20 KB |
| 전체 인덱스 크기 (원본 텍스트) | ~200 TB |
| 역 인덱스 크기 (~3배 압축) | ~60 TB |
| 쿼리 QPS | 10만/초 |
| 일일 새 페이지 인덱싱 | ~3억 |
| 필요한 크롤 처리량 | 초당 3,500페이지 |

## 웹 크롤러(Web Crawler)

크롤러는 세 가지 컴포넌트로 구성된 분산 시스템입니다: **URL 프론티어(URL Frontier)** (크롤할 URL의 우선순위 큐), **페처(Fetcher)** 워커 (HTML 다운로드, `robots.txt` 준수), **링크 추출기(Link Extractor)** (HTML 파싱, 새 URL 추출, 프론티어로 피드백).

- **정중함(Politeness)**: 도메인 레벨 속도 제한 추가 — 같은 도메인은 초당 최대 1회 크롤. 지연이 있는 도메인별 큐 사용.
- **중복 제거(Deduplication)**: Bloom Filter(거짓 양성 허용)로 이미 방문한 URL 재크롤 방지. 100억 URL × 10바이트 기준, Bloom Filter에 ~12 GB 메모리 필요.
- **우선순위화(Priority)**: 높은 PageRank 페이지와 자주 업데이트되는 사이트(뉴스, Wikipedia) 우선화. 점수가 있는 우선순위 큐 사용.
- **DNS 캐싱**: DNS 병목 방지를 위해 도메인별 DNS 조회를 5분간 캐시.

## 역 인덱스(Inverted Index)

역 인덱스는 각 **용어(term)**를 **포스팅 리스트(posting list)**에 매핑합니다: 해당 용어가 포함된 문서 ID(및 메타데이터)의 정렬된 목록. 모든 검색 엔진의 핵심 데이터 구조입니다.

```text
역 인덱스 (간략화):

"python"  → [(docId=42, tf=5, pos=[12,34,67]), (docId=101, tf=2, pos=[3,19]), ...]
"design"  → [(docId=7, tf=1, pos=[4]), (docId=42, tf=3, pos=[1,5,89]), ...]
"system"  → [(docId=7, tf=8, pos=[2,6,...]), ...]

"python system design" 쿼리에 답하는 방법:
  1. 각 용어의 포스팅 리스트 조회
  2. docId 목록 교집합 (AND 쿼리)
  3. 각 문서 점수 계산: BM25(tf, idf, doc_length)
  4. PageRank 신호로 재랭킹
  5. 상위 10개 반환
```

## 랭킹: BM25 + PageRank

검색 랭킹에서 두 가지 신호가 지배적입니다: **BM25**(용어 빈도와 역 문서 빈도를 기반으로 한 문서의 쿼리 관련성)와 **PageRank**(인바운드 링크를 기반으로 한 페이지의 권위). 현대 검색은 학습된 랭킹 모델(LambdaRank, Neural IR)을 사용하지만, BM25 + PageRank가 면접의 정석 답변입니다.

| 신호 | 측정 대상 | 계산 시점 |
| --- | --- | --- |
| TF (용어 빈도) | 문서에서 용어가 나타나는 횟수 | 인덱스 시점 |
| IDF (역 문서 빈도) | 전체 문서에서 용어의 희소성 | 인덱스 시점 |
| BM25 점수 | 쿼리에 대한 문서 관련성 (TF, IDF, 문서 길이 결합) | 쿼리 시점 |
| PageRank | 인바운드 링크 그래프 기반 권위 | 오프라인 배치 (Spark) |
| 최종 점수 | BM25 + PageRank + 신선도 + 클릭의 가중 조합 | 쿼리 시점 |

## 자동완성(Autocomplete)

자동완성은 쿼리 접두사에 대한 상위 K개 완성을 50ms 이내에 반환합니다. 두 가지 주요 접근법은 **트라이(Trie, 접두사 트리)**와 접두사 인덱스가 있는 데이터베이스 기반 접근법입니다. 1억 개의 일반 쿼리의 경우 트라이는 RAM에 맞습니다(~5 GB). 각 노드는 검색 빈도로 미리 정렬된 상위 10개 완성을 저장하며, 쿼리 로그를 처리하는 배치 작업에 의해 매일 업데이트됩니다.

## 확장성 고려 사항

- **인덱스 샤딩**: 용어 해시로 역 인덱스를 샤딩합니다. 각 샤드는 용어 사전의 일부를 보유합니다. 쿼리는 모든 샤드로 병렬 팬아웃됩니다.
- **인덱스 복제**: 장애 허용성과 읽기 병렬성을 위해 각 샤드를 복제합니다.
- **캐싱**: 트래픽의 ~90%를 차지하는 상위 10% 쿼리에 대한 결과를 5분 TTL로 Redis에 캐시합니다.
- **증분 인덱싱(Incremental Indexing)**: 새 페이지는 메인 인덱스와 함께 서빙되는 작은 '델타' 인덱스에 인덱싱됩니다. Spark 작업으로 주기적으로 병합됩니다.
- **PageRank 계산**: 매일 밤 전체 링크 그래프에 대해 Spark GraphX 작업으로 실행합니다. 점수는 랭커가 읽는 키-값 저장소에 저장됩니다.
